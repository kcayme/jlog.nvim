Read JSON server and container logs in Neovim. Logs pulled from servers,
containers and CI are often unformatted, one giant line, and double-encoded.




FEATURES                                                  *jlog.nvim-features*

- **Any JSON log:** JSONL, JSON arrays and timestamped log exports; double-encoded JSON is unwrapped, and nothing is
    dropped or reformatted.
- **Readable view:** one compact line or indented JSON per entry, searchable with `/` and `:g`.
- **Filter and group:** a small query language (`status>=500 -health`), group by any field, and top values per field
    in the sidebar.
- **Big and live files:** the first screen of a 500k-line file in about 100ms, and the view follows the file as it
    grows.
- **Customizable:** field styles, sidebar, keymaps and highlights.


REQUIREMENTS                                          *jlog.nvim-requirements*

- Neovim >= 0.10 (`:checkhealth jlog` confirms it)


INSTALLATION                                          *jlog.nvim-installation*

With lazy.nvim <https://github.com/folke/lazy.nvim>:

>lua
    { "kcayme/jlog.nvim", opts = {} }
<

`setup()` is optional; without it jlog runs with the defaults below.


QUICK START                                            *jlog.nvim-quick-start*

1. Open a log file and run `:JLog` (or `:JLog path/to/app.log`). It opens in its own tab, with the sidebar on the right.
2. Press `<CR>` on an entry to expand it, `E` to expand them all.
3. In the sidebar, type `status>=500` under `FILTERS`, or `request_id` under `GROUP BY`, then `:w`.
4. Or press `<CR>` on values in `FIELDS` to filter by them (one line each, `OR` between values of a field), `g` on a
field to group by it.
5. `?` in the sidebar lists every key; `q` closes the workspace.


USAGE                                                        *jlog.nvim-usage*


OPENING LOGS ~

`:JLog` opens the current buffer, `:JLog {path}` a file; the format is detected
on open. jlog never writes to the source file, and `gf` on an entry shows its
raw source text.


THE LOG VIEW ~

Entries are shown newest first, for JSONL files and timestamped exports alike;
`R` reverses the order and `view.sort = "asc"` makes oldest first the default.
`<CR>` expands an entry in place, `E` switches the whole view between compact
and expanded, `]]` / `[[` move between entries and `]e` / `[e` between errors.
The winbar shows how many entries match and the active filters and group.


THE SIDEBAR ~

- **FILTERS** and **GROUP BY** are typed in the buffer and applied with `:w`, by leaving insert mode, or as you type
    with `sidebar.auto_apply`. One filter clause per line, ANDed; an empty section shows an example.
- **LIMIT** has two labelled lines, applied with `:w` too: a number after `entries` shows the first N entries in
    display order (it follows SORT), and one after `groups` the first N groups of a GROUP BY. With both, the last group
    can be cut short. The labels cannot be edited; leave a value blank for no limit. FIELDS still counts every match.
- **SORT** shows the current order. It is not part of the buffer, so it cannot be edited; `R` reverses it.
- **FIELDS** lists every field with its top values and counts: `<CR>` on a value adds it as a filter, `g` on a field
    groups by it. After a filter or group, the lines show first and the counts follow, dimmed and marked `counting…`
    until they arrive. Counts for fields with more than 1000 distinct values are estimates, marked `~`.

`S` hides or shows the sidebar (nothing is counted while it is hidden), `s`
focuses it. Its sections, their order and how FIELDS lists and styles field
names are configurable: see `sidebar` under |jlog.nvim-configuration|.


LARGE FILES ~

Large JSONL files are parsed on background threads: the first screen shows
right away and the rest loads in the background, with FIELDS adding fields as
they are found (`loading N%`); a timestamped export that has to be reordered
first appears once it has loaded. A log larger than `paging.size` (100k lines
or array elements) is shown one page at a time, so only that page is held in
memory: the winbar shows `page 2/5`, `]p` / `[p` or `:JLog page {n}` move
between pages, and each page also shows `paging.overlap` lines of its
neighbours, dimmed, so a request at a page edge stays whole. Filters, group and
mode carry over to another page.

While a large page is still being drawn, `/` may match the raw text of rows not
drawn yet; it is exact once drawing is done.


LIVE RELOAD ~

The view follows the file: appended lines stream in, and atomic saves, rotation
and a file deleted and created again are followed. A rewritten file returns to
the page holding the entry under the cursor.


PROGRESS MESSAGES ~

Work that outlasts the first screen (loading, indexing pages, applying a filter
or group, rendering) reports one message when it starts and one when it is
done. On Neovim 0.12+ these are progress messages, so a notification plugin
that draws progress can show a spinner; on older versions they go through
`vim.notify`. `progress = "notify"` always uses `vim.notify`, `progress =
"off"` turns them off.

FILTER SYNTAX ~

One clause per `:JLog filter` call or sidebar `FILTERS` line. Every line after
the first starts with its operator: `AND` starts a new condition that must also
match, `OR` adds an alternative to the condition above. A line typed without
one is taken as `AND`, and the operator is written in when the filter applies.

>
    service=user-api
    AND request_id=req-00000001
    OR request_id=req-00000002
<

This reads as `service=user-api AND (request_id=req-00000001 OR
request_id=req-00000002)`.

>
    :JLog filter status>=500 path=/api/licence-checks
<

  -----------------------------------------------------------------------
  Syntax                            Meaning
  --------------------------------- -------------------------------------
  field=value, field!=value         Equality on the value’s text; numbers
                                    also compare numerically
                                    (status=500).

  field>n, >=, <, <=                Numeric comparison; non-numeric
                                    values never match.

  time>=2026-10-22T10:00, <, …      Time comparison when the value is a
                                    date (2026-10-22), a date and time,
                                    or a full ISO time; fields holding
                                    ISO 8601 times compare as instants,
                                    whatever their offset.

  field~regex                       Vim regex (same flavor as /, honors
                                    'ignorecase') against the field’s
                                    string form.

  value                             Bare term: Vim regex against the
                                    entry’s raw source text.

  -term                             Negate a term.

  term term, term AND term          Inside a line, a space or AND means
                                    AND.

  a OR b                            Uppercase OR separates alternatives;
                                    AND binds tighter.

  "quoted value"                    Needed for spaces or the words OR and
                                    AND, e.g. msg="request completed",
                                    "AND".
  -----------------------------------------------------------------------
- Fields are dotted paths (`req.headers.host`). `time`, `level` and `msg` resolve through the configured `fields`
    aliases (e.g. `message`, `severity`); `level` compares case-insensitively.
- A missing field never matches, so `-term` matches it. Filtering while grouped keeps whole groups.
- A condition made only of `field=value` alternatives on one field (picked values on `OR` lines, or
    `status=500 OR status=502`) leaves that field’s FIELDS counts as if it were off, so all its values stay listed to
    pick from; the other fields count only the matches.
- In field names a newline is written `\n` and a backslash `\\`. Inside quotes only `\"`, `\\` and `\n` are
    escapes, so a quoted `~` regex that needs a literal backslash writes `\\\\` (`msg~"a\\\\b"` matches `a\b`).
- A typed time without a zone is local time, like the view shows (UTC with `view.time_utc`); a date alone is
    midnight. Quote one with a space: `time<"2026-10-22 11:00"`. `=` and `~` still match the time’s text.
- Integers are exact at any size: `id=12345678901234567890` works. `>`, `>=`, `<` and `<=` compare as doubles, so
    past 2^53 they are approximate.


CONFIGURATION                                        *jlog.nvim-configuration*

Defaults (all optional):

>lua
    require("jlog").setup({
      fields = {
        time = { "time", "ts", "timestamp", "@timestamp", "time_stamp", "timeStamp" },
        level = { "level", "lvl", "severity" },
        message = { "msg", "message" },
        status = { "status", "status_code" }, -- class-colored (2xx-5xx) when styled inverted/pill
      },
      compact = {
        style = "plain", -- "plain" | "inverted" | "pill"; level defaults to "inverted"
        order = {}, -- top-level keys shown first, e.g. { "method", "path", "status" }
        fields = {}, -- per key or role: { style = "pill", format = function(ctx) return ctx.value end }
        pill = { left = "\238\130\182", right = "\238\130\180" }, -- Nerd Font caps; "" for square ends
        style_values = { "level", "status" }, -- keys or roles styled on the value instead of the key
      },
      view = {
        mode = "compact",
        sort = "desc", -- "desc" shows the newest entries first
        field_colors = true,
        -- os.date format for compact-line times (%L is milliseconds), false for HH:MM:SS.mmm as written, or a function:
        -- function(t) return t.value end shows the time unformatted
        time_format = "%Y-%m-%d %H:%M:%S",
        time_utc = false, -- show time_format times in UTC instead of local time
        ignore_fields = {}, -- field paths left out of compact lines, e.g. { "hostname", "req.headers" }
      },
      unwrap = { enable = true, max_depth = 4 },
      sidebar = {
        width = 45,
        position = "right",
        line_numbers = false, -- show line numbers in the sidebar
        -- apply FILTERS, GROUP BY and LIMIT edits without :w, once edits pause for debounce_ms
        auto_apply = { enable = false, debounce_ms = 300 },
        fields = { -- how FIELDS lists and styles field names
          colors = true, -- false: every name uses JLogFieldName
          style = "plain", -- "plain", "inverted" or "pill", like compact fields
          pill = { left = "\238\130\182", right = "\238\130\180" }, -- Nerd Font caps; "" for square ends
          -- per field path or role, e.g. { level = { style = "pill" } }; a format(ctx) gets ctx.name and ctx.distinct
          -- and returns the name's text and optionally a highlight group
          styles = {},
          pinned = {}, -- field paths or roles listed first, e.g. { "level", "status", "path" }
          -- the other fields: "alphabetical", or "count" (in the most entries first; applied once the counts are final,
          -- so rows hold still while a file loads)
          sort = "alphabetical",
        },
        -- sections in the order shown, e.g. { "fields", "filters", "group" }; one left out is hidden, and :w then keeps
        -- the filters or group that field actions and commands set
        sections = { "filters", "group", "limit", "sort", "fields" },
      },
      facets = { top_values = 10 },
      paging = { size = 100000, overlap = 2000 }, -- source lines (JSONL) or array elements
      progress = "auto", -- "auto" (progress messages on Neovim 0.12+), "notify" (always vim.notify) or "off"
      keymaps = {
        toggle_entry = "<CR>",
        toggle_mode = "E",
        raw = "gf",
        reverse = "R",
        clear = "X",
        next_entry = "]]",
        prev_entry = "[[",
        next_error = "]e",
        prev_error = "[e",
        next_page = "]p",
        prev_page = "[p",
        focus_sidebar = "s",
        toggle_sidebar = "S",
        close = "q",
        add_filter = "<CR>",
        group_by = "g",
        ignore_field = "s",
        help = "?",
      },
    })
<

See docs/options.md <docs/options.md> for every option.


COMPACT LINE FORMATTING ~

Each field of a compact line has a style, set globally with `compact.style` or
per field with `compact.fields[key].style` (`key` is a field name or a role:
`time`, `level`, `message`, `status`):

- `plain`: `key=value`, the key colored per field. Example: `method=GET`.
- `inverted`: the key as a colored block. Example: `method =GET`.
- `pill`: like `inverted`, with rounded caps around the key. Example: `(method)=GET`.

Fields in `compact.style_values` (by default `level` and `status`) are styled
on the value instead (`500`, no key); remove one to give it a styled key.
`level` is `inverted` by default, colored by its level; a styled status value
takes its class color (`JLogStatus2xx` … `JLogStatus5xx`); other fields take
their key’s color. `time` and `message` stay plain unless styled through
`compact.fields`.

`compact.order` lists top-level keys to show first.
`compact.fields[key].format(ctx)` replaces a field’s text: `ctx` has `value`,
`key` and `entry`, and it returns the text and optionally a highlight group. It
runs on every drawn line; if it errors, the default text is used and jlog warns
once per field.

>lua
    compact = {
      order = { "method", "path", "status" },
      fields = {
        method = { style = "pill" },
        duration_ms = {
          format = function(ctx)
            return ctx.value .. "ms", (tonumber(ctx.value) or 0) > 500 and "DiagnosticError" or nil
          end,
        },
      },
    }
<

Pill caps are inline virtual text (never yanked or searched) and need a Nerd
Font; `pill = { left = "", right = "" }` gives square ends.


STATUSLINE PLUGINS ~

The log view shows its counts and filters in the winbar. A statusline plugin
that draws winbars, such as lualine with a `winbar` section, replaces it;
exclude jlog’s filetypes `jlog` and `jlog_sidebar`:

>lua
    require("lualine").setup({
      options = { disabled_filetypes = { winbar = { "jlog", "jlog_sidebar" } } },
    })
<

BENCHMARK                                                *jlog.nvim-benchmark*

On 10k to 500k-line JSONL files, jlog’s load is compared with `jq` and

a workspace; see bench/results.md <bench/results.md>. `make bench` regenerates
